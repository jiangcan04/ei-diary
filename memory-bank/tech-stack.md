# 《ei ？》首版技术栈

依据 [产品设计文档 v1.5](./design-document.md)。首版采用 **Vite + 原生 TypeScript + Canvas 2D + Dexie + Workbox**，交付为从 iPhone 主屏幕打开的离线 PWA。应用文件通过 HTTPS 提供，日记和照片留在设备上。首版无需账号、后端或云同步。保留稳定的页面标识和版本化备份格式，供后续账号或同步设计沿用。

| 层 | 推荐 | 用法 |
|---|---|---|
| 工程与界面 | Vite、TypeScript 严格模式、原生 HTML/CSS、npm | 封面、月历、阅读、编辑四个视图，共用一份明确的导航状态。提交 npm 锁文件，固定一个满足 Vite 要求的 Node.js LTS 版本，构建前独立运行 TypeScript 类型检查。[Vite 官方指南](https://vite.dev/guide/) |
| 手写与拼贴 | Canvas 2D、Pointer Events | 用同一套纸面坐标渲染照片、笔迹和缩略图。画笔与照片摆放是两个操作状态，工具栏和日期是可访问的 HTML 控件。 |
| 纸感与翻页 | CSS、原生 Pointer Events | 封面与路灯使用本地图片素材。阅读模式用两张纸面、裁切和阴影模拟掀角，拖动时只更新显示。系统开启减少动态效果时直接换页。 |
| 本地数据 | IndexedDB + Dexie | 用 Dexie 管理表结构、版本升级及事务。日记页、照片二进制和缩略图分别存储，按页面标识关联。[Dexie 事务文档](https://dexie.org/docs/Dexie/Dexie.transaction()) |
| 安装与离线 | Web App Manifest、Service Worker、Workbox 的 generateSW | 构建后生成有版本的预缓存，覆盖应用入口、脚本、样式、纸纹、封面、路灯和本地字体。日记使用 IndexedDB 保存。[Workbox 预缓存指南](https://developer.chrome.com/docs/workbox/precaching-with-workbox) |
| 整本备份 | ZIP + 版本化 JSON 清单 + 独立图片文件，使用 fflate | 文件内保存可编辑笔迹、日期、页面标识和照片布局。大包分批处理，避免在主线程一次性处理整本图片。[fflate 项目文档](https://github.com/101arrowz/fflate) |
| 测试 | Vitest、Playwright WebKit、iPhone 真机 | Vitest 测日期排序、坐标换算和备份校验。Playwright 测导航、保存失败和导入去重。实际安装、双指手势、相册、离线重启和「文件」备份在真机验收。[Vitest](https://vitest.dev/guide/) · [Playwright 浏览器指南](https://playwright.dev/docs/browsers) |
| 部署 | 固定域名的 HTTPS 静态托管，首版可用 Cloudflare Pages Direct Upload | 上传构建产物即可从 iPhone 访问。日常版保持同一来源，换域名前先导出备份，切换后手动恢复。[Cloudflare Pages 官方说明](https://developers.cloudflare.com/pages/get-started/direct-upload/) |

React、UI 组件库和全局状态库可等界面规模扩大后再评估。首版的复杂度主要在手势、渲染和数据保存，原生界面加少量专用库足以覆盖。

## 实现时最需要守住的边界

- **纸面坐标是数据，画布是显示。** 笔画保留点列、颜色和粗细。照片保存独立位置及大小，画在照片上的圈仍属纸面。缩放或移动视口只改变显示变换。缩略图可重建，不能作为唯一记录。
- **手势由当前模式决定。** 阅读只从纸角起拖。编辑用单指落笔、双指缩放和平移，第二指加入时取消未提交笔画。照片摆放状态单独处理选中与缩放。先用简单裁切和阴影验证跟手感，按真机结果调整。
- **控制照片内存。** 保留导入照片的二进制资源并生成较小的显示图和缩略图，按需解码当前页及邻页。张数不设固定上限，遇到存储不足或格式无法解码时提示原因，并保留已保存内容。真机用多张高分辨率照片验证方向、颜色、拖动和重开。
- **保存完成后才能离开编辑。** 每页串行提交更新，避免旧写入覆盖新内容。页记录和资源引用跨表事务提交，解码和缩略图生成放在事务外。日期按设备本地时间凌晨 02:00 换日，新页创建时确定归属日并独立保存，创建时间另存。写入失败保留编辑中的内容供重试。
- **更新和备份都要保住数据。** 应用新版本等编辑完成后再切换。备份导入前校验版本、条目大小、页面标识与资源引用，按页面标识去重，冲突保留本机版本，失败时保留现有日记。设备本地存储可能被清除，整本备份需在开始长期使用前通过恢复验收。
- **资源随应用离线可用。** 手写字体选择可合法分发且覆盖所需中文和数字的字体，自托管并随应用缓存，检查字形缺失时的回退。纸纹、图标和路灯也随应用打包。

首个真机验证切片是「从主屏幕启动 → 贴五张照片 → 放大手写 → 保存并离线重开 → 导出到文件，在空白环境恢复」。先跑通这条路径，再细调翻页动画和纸面质感。
