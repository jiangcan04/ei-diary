# 《ei ？》实施计划

对照 [产品设计文档 v1.5](design-document.md) 和 [首版技术栈](tech-stack.md) 执行。目标是在 iPhone 主屏幕可安装、离线可使用的手写日记 PWA。

按顺序完成，每步测试通过后再继续。用 Vitest 检查日期、坐标和备份规则，用 Playwright WebKit 检查页面流程和数据异常。涉及安装、触摸、系统相册或「文件」的操作，在 iPhone 真机测试并记录系统版本。每完成一节，按项目说明更新经核对的架构文档。

首版按本机日记流程实施。真机验收从主屏幕打开后直接进入封面，无需登录。账户登录、本机解锁和跨设备同步留待后续版本。

## 一、准备工程

1. **核对实施依据。** 完整阅读设计文档、技术栈和项目说明。编码前核对项目说明里的架构文档和设计文档路径，确认实际位置后再使用。
   - **测试**：逐个打开两份依据和项目说明要求阅读的文件，确认路径可用、需求版本一致，并确认记录架构变更的位置。
2. **建立最小可运行工程。** 用 Vite、严格模式 TypeScript 和原生 HTML/CSS 建立静态入口。固定满足 Vite 要求的 Node.js LTS，提交 npm 锁文件，配置独立类型检查、Vitest 和 Playwright WebKit。
   - **测试**：在干净环境按项目说明完成安装、构建和运行。类型检查通过。运行一个 Vitest 测试，并用 Playwright WebKit 在 iPhone 尺寸打开构建产物，确认无启动错误。
3. **定义日记数据结构。** 为页面分配稳定标识，区分记录日期和创建时间。用设备本地日历保存记录日期，创建时间单独存储。将照片布局和笔画保存为独立的纸面坐标数据。
   - **测试**：构造同日两页和跨日一页。确认标识唯一，改日期保留标识和创建时间，纸面缩放不改变存储坐标。用 Vitest 验证本地时刻 01:59 新建归前一日，02:00 新建归当前日，跨过 02:00 继续编辑时原页日期不变。
4. **建立本机读写。** 用 Dexie 管理 IndexedDB 版本。分别存储页面、照片二进制和可重建的缩略图。用事务提交页记录和照片资源引用，图像解码及缩略图生成放在事务之外。
   - **测试**：写入含照片及笔画的一页，重开后逐项核对。在跨表写入中模拟失败，确认上一版本及其资源引用仍完整。升级库结构后确认旧页仍能打开。

## 二、搭建日记本与月历

5. **建立页面切换。** 串起封面、月历、阅读和编辑四个状态，记住用户离开月历前看的是哪一月。
   - **测试**：从上个月进入阅读再返回，确认仍在上个月。合上本子后重新翻开，确认显示当前月。
6. **制作封面。** 用黑、米白和深浅绿纸片拼出陆地、天空和云，做出书脊与叠纸边。只在本子外左上角显示一次小号手写日期，将本子居中，目标面积约为可用页面的九分之一。整本封面可点，沿书脊掀开。
   - **测试**：首次打开只有一处日期，封面和下方没有文字。本子明显小于页面且约占九分之一。分别点击封面中央与边缘，都能进入月历。
7. **实现月历排布。** 以周一为首列，支持上月和下月，以设备本地 02:00 为界，用柔和绿标记当前日记日期。
   - **测试**：用 2026 年 11 月验证 1 日在周日、30 日在周一，再检查闰年二月、跨年切换和 02:00 前后高亮变化。
8. **完成月历纸面与操作入口。** 将米白日历纸放在剪纸路灯前，遮住灯杆中段。保留手绘加号和合本入口，为图标提供可读的辅助名称。
   - **测试**：在小屏 iPhone 检查灯头和底座可见、日期格不遮挡、加号可点，VoiceOver 能读出入口用途。
9. **接通新建与补记。** 全局加号新建当前日记日期。允许从月历选择具体日期后添页，已有记录的日期也可追加，并保留打开原有缩略图的入口。
   - **测试**：在上个月点加号，校验新页归当前日记日，浏览月份不影响归属。分别为过去的空白日和已有记录日添页，校验新页归所选日期，已有缩略图仍可打开。未写画或贴照片就返回时，确认未产生空白记录。

10. **接入本地视觉资源。** 打包有分发许可的手写字体、纸纹和手绘图标。给图标按钮保留可访问名称，检查字体回退。
    - **测试**：在 iPhone 尺寸检查月份、混合中数字符和画笔、照片、撤销的外观。阻断字体请求后，文字仍可读，图标按钮仍可操作。

## 三、完成编辑与保存

11. **实现纸面落笔。** 用 Pointer Events 捕获落笔，在 Canvas 2D 内渲染连续笔画，记录点列、颜色和粗细，保留原样手写。
    - **测试**：画一个点、一条跨纸面的线和一个手写字。放开手指后笔画完整，画到纸边不触发翻页。
12. **实现笔工具。** 默认炭黑。提供嫩绿、柔和绿、苔绿、深松绿、炭黑和白色，并支持自选色和两档粗细。白色色点带灰边。
    - **测试**：每种色各画一笔，核对颜色、粗细和历史笔画。切换选项后只影响下一笔，白色在深色图像上可辨。
13. **实现撤销和整笔擦除。** 接通整笔橡皮和统一撤销历史。落笔、擦除、照片添加、移除、移动与缩放按操作倒序撤销。一次拖动或缩放记一步，退出编辑清空历史。
    - **测试**：画三笔，撤销最后一笔，再擦掉中间一笔。确认剩余笔画不变。退出重进无历史可撤销。
14. **实现画布缩放。** 单指落笔，两指缩放或移动纸面。识别到第二根手指时清除未提交的临时线条。
    - **测试**：先单指接触再加入第二根手指，放大后写字并缩回整页。确认无多余笔迹，放大前后的内容相对位置一致。
15. **导入多张照片。** 多选和追加后都进入摆放状态。保留原文件并生成较小的显示图，按需解码当前页及邻页，不设置固定张数上限。
    - **测试**：先选三张，再追加两张。确认五张完整出现。取消相册选择时，原有内容完整保留。真机用高分辨率照片检查方向和颜色，模拟无法解码或存储不足时确认提示且旧内容完整。
16. **实现独立摆放。** 允许逐张选中、移动、缩放和移除。点画笔即可退出摆放并在纸上写画。
    - **测试**：分别调整两张并移除一张，确认其余照片未变。点一次画笔，在照片上画圈，再移动该照片，确认圈留在原纸面坐标。再移动一张照片，画一笔，确认两次撤销依次还原笔画与照片。
17. **接通自动保存。** 按页面串行提交笔画结束、照片变更和日期修改后的保存，返回前等最后一次写入完成。失败时保留编辑内容并显示重试。
    - **测试**：落笔后立即返回并重开，确认笔迹已存。模拟一次保存失败，确认留在编辑页，重试后只出现一页。制造旧写入延迟，确认较新的笔画没有被覆盖。
18. **实现修改日期。** 在编辑页通过日期入口补记或调整过去的记录日期，保留内容、标识和创建时间。
    - **测试**：把含多图的一页改到前一月，检查原日期和新日期的记录数量，并从新日期打开核对照片与笔画。
19. **实现删除确认。** 在编辑菜单中提供删除整页操作，确认后更新月历。
    - **测试**：先取消删除，检查原页完整。随后确认删除，检查页面消失且重开仍未出现。

## 四、接通月历预览与阅读

20. **生成月历缩略图。** 用和阅读共用的 Canvas 2D 渲染规则，从保存内容生成小尺寸照片和笔迹预览。当天多页以最新创建页为顶图并显示叠页。
    - **测试**：分日保存纯照片、纯手写和混合页。确认三种都能预览。同日追加一页后，点该格打开顶图所对应的页面。
21. **完成单页阅读和当天页签。** 一次渲染一页，按创建顺序展示当天页签，沿用编辑页的纸面坐标。
    - **测试**：在同一天三页间切换，核对每页内容。编辑第一张再返回，确认其顺序未改变，回月历仍定位原月份。
## 五、离线与备份

22. **配置 PWA 安装。** 配置 Web App Manifest、安装图标和独立显示入口。在固定来源的 HTTPS 静态托管上提供构建产物，首版可用 Cloudflare Pages Direct Upload。
    - **测试**：在 iPhone Safari 添加到主屏幕，从图标启动，确认直接进入合上的日记本，无登录或解锁步骤。
23. **缓存离线应用资源。** 构建后用 Workbox generateSW 生成带版本的预缓存，覆盖入口、脚本、样式、封面、路灯、纸纹和本地字体。应用更新等编辑完成后再切换。
    - **测试**：首次联网加载后关掉应用，开飞行模式从主屏幕重开。添页、贴入一张本机照片并重启，核对内容。编辑途中安装新版，确认未强制重载，编辑结束后可更新且旧日记可读。
24. **导出整本备份。** 用 fflate 将版本化 JSON 清单和独立图片打成 ZIP。清单记录日期、标识、创建时间、可编辑笔画、照片布局和资源引用。分批处理大包，从月历右上角手绘「···」进入导出，将备份保存到「文件」。
    - **测试**：导出含纯手写和多图页面的本子，确认能从「文件」选回备份，并核对包内页数与原本一致。
25. **导入与恢复。** 从月历右上角手绘「···」进入恢复。校验 ZIP、清单版本、条目大小、页面标识及图片引用，显示页数，确认后按页面标识去重合并；冲突时保留本机版本。导入失败保留原有数据。
    - **测试**：在空白环境恢复并逐页核对，确认还能修改笔迹和照片。重复导入不增页。有冲突时本机版本保留，损坏备份不改变现有日记。
## 六、完成翻页与交付

26. **实现跨日顺序。** 按日期与创建时间排列可翻的页面，跳过无记录日期；在首尾禁用无目标方向。
    - **测试**：创建 18 日两页、16 日一页，留空 17 日。沿旧页方向跨到 16 日，再反向翻回 18 日，检查日期和页签同步更新。用两天各三页验证从较新日期第一张向旧翻落在较旧日期最后一张，反翻回到原页。
27. **实现掀纸角交互。** 仅在阅读状态从纸角起拖，用两张纸面的 CSS 裁切和阴影，在拖动时露出邻页。过阈值换页，短拖回落；纸角也可点按。尊重系统减少动态效果设置。
    - **测试**：在 iPhone 上分别测试短拖、长拖、点按、页面中部横划和编辑时落笔。开启减少动态效果后，确认可以直接换页。

28. **完成首版真机验收。** 执行设计文档中的全部 iPhone 场景。有兼容 iPad 时补做 Apple Pencil 基本落笔及缩放。
    - **测试**：记录从点加号到贴一张照片、写一个字并返回所需时间，目标为熟悉操作后十几秒。核对封面、月历缩略图、跨日翻页、白色笔迹、关闭重开后的数据和备份恢复；未通过的项目修复并复验。

## 七、上线后的界面调整

以下步骤依据用户于 2026-11-19 确认的界面调整追加，状态均为待实施。第 1 至 28 步保留为首版历史。后续实施涉及旧版设计中的底部工具栏、展开笔设置及月历日号时，以本节已确认的要求为准，并同步更新设计文档。每次执行一步，由用户验证通过后再继续，并记录进度及实际文件职责。

29. **修复跨设备手写字体。** 检查 iPhone Safari、主屏幕 App 和电脑上的字体请求、字形覆盖、字体声明和缓存版本，定位系统字体回退的原因。让月份、日期、按钮和应用内表单文字使用同一份本地手写字体，覆盖新增界面文字。将修正后的字体纳入离线缓存。
    - **测试**：在电脑和 iPhone 上对照同一月份、日期及工具名称，核对手写字形。验证首次加载、更新旧版本及离线重开均能使用字体。阻断字体加载时确认回退文字可读、操作可用。

30. **建立紧凑的阅读和编辑页顶栏。** 去掉画面上可见的「阅读」「编辑」大标题，保留辅助技术识别页面的名称。编辑页顶部安排返回、小日期及菜单，阅读页保留返回、小日期、编辑及当天添页入口，同日页签紧凑排列。
    - **测试**：从月历进入阅读和编辑，确认大标题消失。核对返回原月份、修改日期、删除确认及阅读后继续编辑均可用，VoiceOver 能识别页面和按钮。

31. **将笔设置改为顶部常驻工具栏。** 在编辑页顶栏下方、画纸上方直接排列画笔、整笔橡皮、细笔与粗笔、绿色系及黑白色点、自选色、照片和撤销。取消原有画笔展开面板。手机窄屏保持一条横向工具栏，容纳不下的工具可横向滑动访问。明确当前工具、颜色、粗细及撤销可用状态。
    - **测试**：进入编辑即可找到笔设置。依次换色、换粗细、擦除、选照片和撤销，核对只影响相应操作。横向滑动工具栏时画纸不产生笔迹，所有工具可访问，控件有可读名称。

32. **整理照片摆放的操作入口。** 保留顶部照片导入和进入摆放的入口，选中照片时显示缩放与移除操作。点画笔恢复书写。照片操作区随选中状态收起，避免持续占用画纸空间。
    - **测试**：导入并追加多张照片，分别移动、缩放和移除。核对选中状态、退出摆放、画圈后移动照片，以及统一撤销顺序。取消选图时保留已有内容。

33. **扩大阅读和编辑画纸。** 阅读与编辑采用靠近满宽的大画纸布局。默认状态下画纸可见区域高度至少占应用可用视口高度的 80%，系统状态栏、浏览器地址栏及设备安全区按实际可用视口计算。顶部导航、工具栏和页签占用紧凑空间。以原有纸面坐标等比显示内容，视口可容纳更大的纸面区域，通过缩放和平移查看整张纸。阅读折角与邻页使用同一显示变换。
    - **测试**：在 iPhone Safari 和主屏幕 App 中分别测量画纸可见高度占比，确认默认状态达到 80%，并核对横竖屏及地址栏收起后的适配。打开改版前保存的照片与笔迹，核对内容比例及相对位置。检查双指缩放、边缘落笔、纸角翻页、照片摆放，以及临时操作区收起后恢复大画纸。

34. **让月历作品占满日期格。** 有记录的日期格隐藏可见日号，用当天最新页缩略图铺满格内可用区域，保持作品比例和内容可辨。同日多页保留叠页效果。空白日期保留日号。今天有作品时用细绿边框标记格子，空白时保留日号绿圈。为作品入口保留日期及页数的辅助名称，点击作品直接阅读，从阅读页小「＋」为该页所属日期添页。月历底部全局加号仍按当前日记日新建。
    - **测试**：分别检查空白日、单页日、多页日及今天，核对日号显隐、缩略图尺寸、叠页和绿色标记。点作品打开最新页，再从阅读页为该日添页，核对归属日期。跨过凌晨 02:00 后检查今日标记，VoiceOver 能读出作品日期与页数。

35. **完成改版回归与真机复验。** 调整已有测试中依赖大标题、画布旧尺寸、展开面板和月历日号入口的断言，使其按新的交互验证。运行类型检查、单元测试、生产构建和 WebKit 回归，由用户在同一部署地址更新后复验界面。
    - **测试**：在 iPhone 17、iOS 27.2 和电脑上对照字体，确认顶部常驻工具、大画纸及月历作品格符合要求。用旧日记完成画笔、拼贴、改期、删除取消、跨日翻页、离线重开及备份往返。编辑过程中发布更新，确认修改保存后可切换新版。记录各项实际结果，用户确认后更新进度和架构文档。

### 第 35 步复验记录（用户确认通过）

在项目根目录依次运行 npm run typecheck、npm test、npm run build、npm run test:e2e。WebKit 现有四个流程分别覆盖界面与整本备份往返、自动保存及失败重试、离线与等待更新、跨日顺序及纸角交互。第 35 步补充离线重开时实际加载手写字体的断言。

部署目标为用户已提供的 https://ei-ni-kan.pages.dev/。构建通过后，将 dist 上传到原 Cloudflare Pages 项目，在手机联网打开并完成应用更新，然后执行下表。用户已整体确认本轮复验通过，以下结果依据该反馈记录。
